# Changelog

Every library in Ballast carries the same version. Each shared version has one section here, newest first.

## 0.1.0-preview.1

Not yet published. The first preview: the libraries listed below, all new.

### Added

- **Ballast.Errors**: an error type with stable codes, the problem answer shape, and a reader for problem answers.
- **Ballast.Paging**: a page request with safe limits, an overflow-safe offset, and the paged result shape.
- **Ballast.Time**: time zone lookup, place time, and a local clock that stays in one zone.
- **Ballast.Text**: accent-free text folding and a personal-data masker.
- **Ballast.Geo**: coordinate checks, distance, bounding boxes and polygon containment.
- **Ballast.Money**: currency codes, rounding to minor units, line totals and money formatting.
- **Ballast.Translations**: parity checks for .resx and JSON translations (the same keys, no blank text, the same placeholders, a same-text allow-list) and a scan for the keys source code asks for. A build task (`BallastI18nBaseName`) also generates a site's culture JSON files and its i18n data script from its .resx files, writing the same bytes as the Node script it replaces for a real site's files.
- **Ballast.Email**: e-mail through SendGrid's web API without an SDK, the send rules and address shape check, and a send-once ledger over an app's store.
- **Ballast.Storage**: atomic file writes (overwrite or create-new), removal of leftover temporary files, safe relative paths with a reason for each refusal, the data folder check, and file types read from the first bytes.
- **Ballast.AspNetCore**: problem answers with a stable code and trace reference, exception mappings, a 404 for unknown API routes, fixed-window rate limits, security headers, startup secret checks and forwarded headers from a proxy list.
- **Ballast.Health**: readiness and liveness routes, build info, database and schema checks, startup gates, warm-up and a startup hold.
- **Ballast.Http**: outbound HTTP safety: the public-address guard, one redirect rule set, capped bodies, per-host credentials, safe URLs for logs, Retry-After resilience, and a polite fetcher.
- **Ballast.SqlServer**: SQL error classifiers that look through the whole exception chain, an enum-to-text and restrict-deletes model convention, a retrying transaction helper, a claim helper, a sequence read, a `GO` batch splitter, an isolation-level reset interceptor, a collation check and a developer-database check for connection strings.
- **Ballast.Admin**: the content security policy, cache rule and headers of a staff console's static files (no inline script, no outside origin unless named, no indexing, no referrer), and the "who am I" answer with the signed-in person's roles, permissions and full-access flag.
- **@ballast/web** and **@ballast/admin** (JavaScript, classic scripts with a CommonJS fallback for Node tests): browser helpers for pages (escaping, the instant of a server string, problem answers, a translation loader, place and event times), and for staff consoles (sign-in state with one shared refresh, the page shell, the sign-in page with Microsoft's return, and a staff-and-roles page behind a data adapter). Not on npm yet: `npm pack` makes the tarballs, and `scripts/vendor-copy.mjs` copies them into an app's `wwwroot`.
- **Ballast.Jobs**: a SQL Server application lock held on its own connection, so only one copy of an app runs its background writes during a deploy; leader-only hosted services, a 409 for admin actions a non-holding copy refuses, and a readiness check for the lock.
- **Ballast.AppAttestation**: Play Integrity app sessions for an API: a nonce-first verdict check, a stateless signed session token, a gate that refuses data calls without one (log-only until enforced), a one-use web ticket that sets an HttpOnly cookie, developer-certificate sideloads, the Google decoder, and nonce and ticket stores behind an interface with an in-memory default.
- **Ballast.Feedback**: the feedback request with its length caps, a manager over an app's store that checks and saves a message and reads it back for triage, and a client that posts it and reports one of six outcomes.
- **Ballast.AppUpdates**: the build check: the version answer read from the `AppVersion` configuration section and its manager, the client that asks it (404 means no minimum), the pure update rules, the store contract, and the install channel names.
- **Ballast.Maui**: phone app plumbing for .NET MAUI, unreleased: owner-sealed on-device storage with one shared key, a one-time sweep of old temporary files, connectivity state, HTTP client setup that refuses a certificate override outside a debug build, the AdMob banner and native-card rules, the localisation runtime, crash reports scrubbed before they are offered, permission asks, the store review prompt policy and view helpers.
- **Ballast.Auth**: sign-in for a web app: rotating refresh tokens with reuse detection, short access tokens with an instant cut-off, lockout and the enumeration guard, ASP.NET Core Identity over Entity Framework (string or int keys), single-use e-mail sign-in links, Google sign-in, Microsoft staff sign-in, and a signed access token for an account outside Identity. Also: the role and permission claims read from the store on each request, with per-user cache eviction (`AddBallastDynamicClaims`, `DynamicClaimsCache`); a seed password generator; and the directory sync's last-run record for an admin page (`AddBallastMicrosoftSyncStatus`, `MicrosoftSyncStatus`).
- **Ballast.Testing**: SQL Server test databases named per run, with a sweep of the leftovers a killed run left behind; captured logs, a scripted HTTP handler and factory, answer builders, a loopback server, SQL exception builders, in-memory and API test hosts, and the source guard kit (repo root, comment-stripping source scan, allow-lists with reasons, a planted-violation self-test, a clock scanner and the migration-safety guard with its markers). The API test host now stops and disposes the host before its teardown drops the database, so a hosted service that uses the database no longer fails at the end of a run.
- **Ballast.Build**: a development-dependency package with no assembly: nullable and analyzer settings, analyzer severities in a global config, a NuGet audit that fails the build on a moderate advisory or higher, and a build-time stamp (`BallastBuildTimeUtc`, written as `BuiltAtUtc` for `/health`) that must be an exact UTC time. Its symbols package is off, because an assembly-less package has no symbols.
- **Ballast.Deploy** (a PowerShell 7 module, not a NuGet package): the deploy steps from a pushed commit, with the config read from the app's own file, the migration guard with its exact markers, exit codes that stay fixed, and a refusal of the warm-up settings. Tooling also gains a reusable .NET CI workflow with two wait actions, a SQL Server service in Ballast's own CI, and Ballast's Semgrep rules. Follow-up: throwaway data folders (`ThrowawayDirectories`), a standalone apply of a commit (`-Ref`, with the bundle built when `-BundlePath` is left out), a preflight of the .NET SDK (`MinimumSdkMajor`) and of dotnet-ef, and a rehearsal database (`-Database`).
